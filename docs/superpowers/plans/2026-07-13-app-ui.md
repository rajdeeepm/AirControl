# AirControl App UI (Spec 5) Implementation Plan

> **For agentic workers:** Executed task-by-task (Codex for backend + scaffold; Claude with the impeccable skill for screen design). Orchestrator commits. TDD throughout.

**Goal:** IPC v2 query/mutation surface, hotkey mapping action, and the React UI (Status / Library / Mappings / Settings) with skeleton animations from stored trajectories.

**Tech Stack:** Python (existing daemon), TypeScript + React 18 + Vite + vitest in `ui/`. No UI network access beyond `ws://127.0.0.1:8787`.

## Global Constraints
- Python tests: `env/bin/python -m pytest -p no:cacheprovider`; all 289 stay green.
- Node: use the system node (v23); everything under `ui/` (node_modules included); never touch files outside the project.
- IPC envelope stays `"v": 1`; additions are new `type` values only — existing clients must not break.
- Privacy: no frames anywhere; trajectories only; UI receives landmarks, never images.
- Codex must NOT git commit; orchestrator commits.

### Task 1: IPC v2 commands + daemon handlers
**Interfaces:**
- `ipc.py`: extend `_COMMAND_NAMES` with `list_library`, `set_mapping`, `delete_gesture`, `rename_gesture`, `get_metrics`, `get_settings`, `delete_everything`. Commands may carry `id: str` (client-chosen) and command-specific fields (`gesture_id: int`, `name: str`, `action: dict`, `context: str = "global"`). `parse_command` validates per-command required fields.
- New event builders (all include `v:1`, plus `id` when replying to a command):
  - `library_event(gestures: list[dict], id)` — each gesture: `{id, name, description, exemplar_count, confirms, rejects, threshold_offset, mapping: dict | null, animation: {timestamps: [...], frames: [[x,y,z]*21, ...]} | null}` (animation = first stored exemplar downsampled to ≤ 30 frames).
  - `metrics_snapshot_event(snapshot_fields..., id)`, `settings_event(payload: dict, id)`, `ack_event(id, ok: bool, error: str = "")`.
- `daemon.py`: `command(name)` grows to `command(message: dict)` internally (keep the public `command(name: str)` signature working by wrapping); handlers: `list_library` reads store (gestures/stats/mappings/first exemplar → downsample), `set_mapping` upserts + `ack`, `delete_gesture`/`rename_gesture` + `ack` + matcher refresh, `get_metrics` → snapshot event, `get_settings` → effective config summary dict (clutch mode, gate thresholds, camera index, db path), `delete_everything` wipes store + matcher refresh + `ack`. All store-less (store=None) cases reply `ack(ok=False, error="no store")`.
**Tests (`tests/test_ipc_v2.py`):** parse_command accepts/rejects per-command fields; each handler against `Store(":memory:")` seeded via existing test helpers; correlation id echoed; animation ≤ 30 frames and 21 landmarks each; delete_everything wipes and acks; backward compat: bare `command(name="get_status")` still works.

### Task 2: hotkey mapping action
**Interfaces:** `ActionKind.HOTKEY = "hotkey"`; `Action` gains `keys: tuple[int, ...] = ()`; `controller.dispatch` HOTKEY → `sink.hotkey(*action.keys)`, description `"HOTKEY · " + names`; `pipeline._mapped_action` accepts `{"kind": "hotkey", "keys": [ints 1..0xFE]}` (validate list of ints, length 1..4); `InputConfig.allow_risky_hotkeys: bool = False`; risky combos (`ALT+F4`, `LWIN+L`, any combo containing `VK_DELETE` with ALT+CTRL) rejected at mapping-dispatch time with a warning log unless flag true. Undo: HOTKEY not reversible (note_fire clears slot).
**Tests:** mapping JSON → dispatch through DryRun sink records hotkey event; malformed keys logged+skipped; risky combo blocked by default, allowed with flag; undo after hotkey fire returns None.

### Task 3: UI scaffold + core libs
- `npm create vite@latest ui -- --template react-ts` layout committed manually (no interactive scaffold): `package.json` (react, react-dom, typescript, vite, vitest, @types/*), strict tsconfig.
- `src/lib/types.ts`: TS mirrors of v1 events/commands (discriminated unions on `type`).
- `src/lib/ws.ts`: `AirControlClient` — connect/reconnect with backoff, `request(command): Promise<reply>` correlating on `id` (uuid), `on(eventType, cb)` bus, connection-state observable. Unit-tested with a mock `WebSocket` class (vitest).
- `src/lib/skeleton.ts`: `drawSkeletonFrame(ctx, frame, bounds)` + `SkeletonLooper` (rAF loop over animation frames, auto-fit, handedness-agnostic); bone list = MediaPipe hand connections; pure-math helpers (`fitBounds`) unit-tested.
- Verify: `npm install && npm run build && npx vitest run` green in `ui/`.

### Task 4: Screens (impeccable design pass)
- `App.tsx` shell: sidebar nav, connection badge, dark theme; Status (armed state, live feed of action/candidate events with confidence + reason, metrics tiles), Library (gesture cards + `SkeletonLooper` canvas + stats + rename/delete), Mappings (curated verb catalog per §10 categories + shortcut recorder using `KeyboardEvent` → VK mapping table + assignment UI + risky flags), Settings (read-only effective settings, privacy panel, delete-everything double-confirm).
- Curated verb catalog: static TS data mapping label → action JSON (media/play-pause → `{"kind":"hotkey","keys":[0xB3]}` etc. — VK constants documented inline).
- Loading/empty/error states for every screen; no unstyled flashes; keyboard accessible.
- Verify: vitest component smoke (render each screen with mock client) + `npm run build`.

### Task 5: Launcher + smoke + docs
